TITLE: One AI Assistant for Several Locations: How to Set It Up Without Confusing Customers

EXCERPT: How multi-location businesses can use AI chat: one assistant or one per branch, structuring location details, routing, hours, booking, consistency.
CLUSTER: AI Receptionists
MOD: 2026-09-27
P: A business with more than one location has a specific problem: customers do not ask 'what are your hours?', they ask 'what are your hours in the Northfield shop?'. A single generic answer is wrong for most of them. Some questions apply to the whole business, such as your brand promise or your return policy, while others belong to one branch: the address, the opening times, who works there, which services are offered and how to book. If an AI assistant mixes these up, it can send a customer to the wrong address or promise a service the nearest branch does not offer. This guide explains the two ways to set up chat for several locations, how to structure the information so the assistant gets it right, how to route conversations and bookings, how to keep the brand voice consistent and how to test before going live. It also explains what Crescelo does and does not do, so you can choose the right structure.
H2[the-two-structures]: The two structures
TABLE:
H: Approach | How it works | Best for
R: One assistant for the whole business | A single knowledge base with a clearly labelled section for each location; the assistant asks or infers which branch | Small groups of two to five locations that share most services and policies
R: One assistant per location | Each branch has its own assistant, knowledge base, hosted page or website widget | Locations with different services, staff, hours or brands, or separate teams managing them
P: Neither is universally better. One assistant is simpler to maintain and keeps the brand consistent. Separate assistants keep each branch's information clean and let each team manage its own content. Many businesses start with one and split later.
H2[approach-1-one-assistant-many-locations]: Approach 1: one assistant, many locations
P: The key is that every location's facts are labelled with the location's name in the text itself. Retrieval works on passages of text, so a passage reading 'Opening hours: Monday to Friday, 9 to 5' cannot be attributed to a branch unless the branch is named in it.
UL:
- Create one short document per location, starting with its name, address and area.
- Repeat the location name in each section: 'Northfield: opening hours', 'Northfield: parking', 'Northfield: services'.
- Put shared policies, such as refunds and privacy, in a separate company-wide document.
- Add a short instruction: 'If the visitor has not said which location they mean, ask them before giving hours, addresses or availability.'
- List which services each location offers, so the assistant does not promise treatments the branch lacks.
TABLE:
H: Content | Where it goes
R: Company story, values, brand voice | Company-wide document
R: Refunds, privacy, cancellation rules that apply everywhere | Company-wide document
R: Address, hours, phone, parking, transport | One document per location
R: Services and prices that differ | Per-location, labelled clearly
R: Local promotions and events | Per-location, with end dates
H2[approach-2-one-assistant-per-location]: Approach 2: one assistant per location
OL:
- Create an assistant for each branch and give it its own name, welcome message and colours if you want each to feel local.
- Load a knowledge base containing the shared company documents plus that branch's own documents.
- Install each widget on the matching page of your website, or give each branch its own hosted page or link.
- Set each branch's opening hours and booking settings in its own assistant.
- Assign a person at each branch to review the unanswered questions weekly.
P: Plans limit how many assistants and hosted pages you can have; Crescelo's Starter, Growth and Agency plans allow one, three and seven hosted pages respectively, so check that your plan covers your number of branches. See [pricing](/pricing).
H2[routing-visitors-to-the-right-branch]: Routing visitors to the right branch
UL:
- Ask early: 'Which location are you interested in?', with the branch names as quick-reply suggestions.
- Where a page belongs to a branch, install the branch's assistant on that page so no question is needed.
- For enquiries that cross branches, for example 'Which of your shops is nearest to me?', include a list of areas each branch serves; see [service area verification](/blog/service-area-verification-ai-chat).
- Capture the preferred branch with each lead so the right team follows up.
- Make it easy to switch: 'Would you like information for another location?'
H2[booking-across-locations]: Booking across locations
P: Crescelo's built-in booking uses one set of opening hours and one slot length per assistant, and it hides slots that are taken. It does not assign staff or handle several rooms. For several locations, the cleanest pattern is a separate assistant and booking calendar for each branch, so hours and availability are never mixed. Alternatively, link each location to its own Calendly or Cal.com page. Whichever you choose, make sure the confirmation email names the location and address, because that is the detail customers most often get wrong.
H2[keep-the-brand-consistent]: Keep the brand consistent
UL:
- Write the tone instructions once and reuse them for every assistant.
- Use the same core documents for policies and company facts, updated in one master copy.
- Agree on wording for common situations such as complaints and refunds.
- Review each assistant's conversations against the brand guidelines each quarter.
- Decide who can change instructions and documents; see [securing your account with roles](/blog/setup-rbac-2fa-team-security).
P: See [making the assistant sound like your business](/blog/brand-voice-alignment-ai-receptionist) for a tone guide.
H2[handling-local-differences]: Handling local differences
TABLE:
H: Difference | How to handle it
R: Different opening hours | State hours per location, with special dates in the same document
R: Different services | List services per location; say 'not available at Northfield' where relevant
R: Different prices | Name the location beside each price
R: Different languages | Add the language spoken at each location; Growth includes a multilingual switcher
R: Different contact channels | Give each branch's own phone and email
H2[test-before-you-launch]: Test before you launch
OL:
- Ask the same question for each location and check that the answer names the right one.
- Ask without naming a location and confirm the assistant asks which one.
- Ask about a service only one branch offers, at another branch.
- Ask for directions and parking at every location.
- Try a booking at each location and check the confirmation email.
P: Repeat after every change, and keep the question list as a regression test.
H2[common-mistakes]: Common mistakes
UL:
- Putting all hours into one paragraph without location names.
- Forgetting to update one branch's document when something changes.
- Letting each branch write its own tone.
- Not capturing which branch a lead wanted.
- Using one booking calendar for locations with different hours.
- Never asking staff at each branch to review answers.
H2[frequently-asked-questions]: Frequently asked questions
FAQ:
Q: Should I use one assistant or one per location?
A: One assistant suits a few similar locations. Separate assistants suit branches with different services, staff or hours.
Q: How does the assistant know which location a visitor means?
A: By asking, or by being installed on that branch's page. Instruct it to ask when the location is unclear.
Q: Can one booking calendar cover several locations?
A: Not cleanly. Use a separate assistant and calendar per branch, or link to each branch's own scheduling page.
Q: How many assistants can I have?
A: That depends on your plan. Check the pricing page for the current limits.
Q: How do I keep the brand voice consistent?
A: Reuse the same tone instructions and company documents for every assistant, and review conversations regularly.
Q: What is the biggest risk?
A: Location facts that are not labelled with the branch name, so the assistant gives one branch's details for another.
